AppWorld Tool-Tree Pipeline

Process map for the hierarchical tool-tree MVP in tool-tree-demo. This document describes how official AppWorld API docs become fused similarity matrices, six binary linkage trees, three selected trees, dynamic cluster cuts, and Plotly structural artifacts. Existing artifacts live under artifacts/appworld/ (local/gitignored). Exploratory notebook: notebooks/tree_pipeline_exploration.ipynb.

End-to-end flow

1. Ingest — Phase 1
457 tools

Load official AppWorld API docs via installed PyPI package appworld==0.1.3.post1. Normalize to ToolRecord with stable tool_id = app_name.api_name.

  • Code: src/tool_tree_demo/loader.py, artifacts.py
  • CLI: uv run tool-tree load-appworld
  • Artifact: artifacts/appworld/run-a/tools.jsonl + manifest.json
↓
2. Enrich — Phase 2A / 2B
keywords + taxonomies

Keyword enrichment (LLM, cached) and transformer classification into approved flat taxonomy_v0 functional and domain distributions.

  • Adapters: adapters/doc_enrichment_bridge.py, adapters/transformer_classifier_bridge.py
  • Artifacts: phase2b/keywords/enrichments.jsonl, phase2b/classification/classifications.jsonl, phase2b/taxonomies/taxonomy_v0/*.json
  • Human gate G2: taxonomy definitions approved as immutable taxonomy_v0
↓
3. Similarity layers + fusion — Phase 3 / 3B
independent matrices

Compute one normalized pairwise similarity matrix per feature over the same 457 tool IDs. Fuse with named weight profiles (never concatenate heterogeneous vectors).

Feature layers description embedding · functional taxonomy · domain taxonomy · keywords (TF-IDF / Jaccard) · app-family exact match
Phase 3B reduced profiles functional_dominant, domain_dominant, mixed_low_app each as raw_convex and variance_calibrated
  • Config: config/phase3b_reduced_profiles.v1.json
  • Artifacts: phase3b/profiles/*.npz (457×457)
↓
4. Hierarchical binary trees — Phase 4A
6 trees

Average-linkage (SciPy) on D = 1 − S for each fused profile. Emit SciPy Z-matrix + canonical membership-hashed binary tree (913 nodes = 457 leaves + 456 internals). Optional coarse/medium/fine packed presentation views.

  • Adapter: adapters/linkage_cluster_packer.py (from text_analyzer/.../cluster_packer.ipynb)
  • Artifacts: phase4a/trees/<profile>/{linkage,canonical_tree,packed_*}.json
  • Diagnostics: phase4a/structural_diagnostics.json
↓

3 of 6

6. Intrinsic labels — Phase 4B1
cached LLM

Membership-keyed intrinsic summaries for internal nodes (concise v3 run). Contextual contrast prose is deferred (Phase 5D / formerly 4B2).

  • Artifact: phase4b1/intrinsic-run-v3/successful_records.jsonl (812 summaries)
  • Occurrence refs: phase4b1/intrinsic_occurrence_references.jsonl
↓
7. Dynamic cluster cuts — Phase 5A
3 trees × 3 cuts

Join intrinsic labels + leaf payloads onto the three selected binary trees, then cut each into nested hierarchical cluster trees that only expose existing canonical memberships.

  • Adapter: adapters/dynamic_tree_cutter.py (build_dynamic_cut() — SciPy top cut + recursive width-bounded subcut
  • Cuts: cluster_count_10, cluster_count_25, distance_half_root
  • Config: config/phase5a_intrinsic_trees.v1.json
  • Artifact: phase5a/trees/<tree>/intrinsic_labeled_tree.json (self-contained: linkage, nodes, labels, embedded dynamic_cuts)
↓
8. Plotly nested structures — Phase 5B
9 structures

Convert each embedded cut to Plotly treemap row data (ids / parents / labels / values) without reconstructing linkage or inventing memberships.

  • Adapter: adapters/plotly_nested_structure.py · convert_phase5a_cut()
  • Artifact: phase5b/structures/<tree>/<cut>/plotly_nested_structure.json
  • Diagnostics: phase5b/diagnostics/structural_coherence.json
↓
9. Local label review UI — Phase 5C
G5C gate

Offline D3 outline over all nine Phase 5B structures. Human flags intrinsic label quality; reviews directory currently empty.

  • Serve: uv run tool-tree serve-phase5c
  • Bundle: phase5c/app/data/review_bundle.json
↓

Where “spoilage” can hide

The repository does not document a named “spoiled trees” incident. When trees look wrong, inspect these seams in order: fused matrix symmetry / scale → linkage Z-matrix vs tool ID order → canonical membership hashes → dynamic-cut fidelity to canonical nodes → Plotly row parent/id coherence → intrinsic label content (often the human-visible failure mode even when structure is valid).

Load-time finding: Phase 5A files are newer than Phase 5B (mtime ~2026-07-29 vs ~2026-07-26). Live validate_structure() fails for mixed_low_app_variance_calibrated on cluster_count_10 and distance_half_root because one shared cluster’s cached Plotly intrinsic_summary.scope_boundary no longer matches Phase 5A (display label still matches: “Cross-platform logout”). Stored Phase 5B diagnostics still say passed. Functional and domain trees validate cleanly.
Structural integrity Phase 4A / 5A / 5B verifiers already assert leaf partition completeness, membership-hash fidelity, and Plotly coherence. Use structural_diagnostics.json and structural_coherence.json.
Semantic / label quality Intrinsic summaries can enumerate domains instead of abstracting them. Structure may be fine while the outline “looks spoiled.” Phase 5C flags exist for this review.
