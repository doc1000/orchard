Taxonomies

A taxonomy is a label set plus a ModernBERT+logistic scorer. You usually write a new one and train the head. The packaged Domain / Function heads are a convenience, not the main workflow.

Primary path

1) Define labels (name + definition). 2) Encode texts with ModernBERT. 3) Fit logistic. 4) load_head onto the taxonomy. Training text is label descriptions, labelled documents/chunks, or both. Needs orchard[taxonomy-ml].

What you get

taxonomy.transform(documents) returns [n, k] probabilities (one row per document, one column per label). Orchard turns those rows into a similarity layer (default Jensen–Shannon) and builds a tree named after the taxonomy.

Create a new taxonomy (tiny example)

Same definition object for every path below. cues are optional extra training phrases for the description-only path. They are not the scorer.

from orchard import TaxonomyModel

topic = TaxonomyModel.from_definition({
    "schema_version": "orchard_taxonomy_definition_v1",
    "name": "topic",
    "label_order": ["mail", "calendar"],
    "labels": [
        {
            "label_id": "mail",
            "name": "Mail",
            "definition": "Email, inbox, threads, drafts, and messages.",
            "cues": ["inbox", "reply-all", "email digest"],
        },
        {
            "label_id": "calendar",
            "name": "Calendar",
            "definition": "Events, meetings, reminders, and scheduling.",
            "cues": ["meeting", "reminder", "schedule"],
        },
    ],
})
topic.save("topic.json")   # optional; reload later with TaxonomyModel.load("topic.json")

Input: name (becomes the tree id), label_order, and per-label name + definition.
Result: a TaxonomyModel with no head yet. Do not pass it to OrchardBuilder until you attach a ModernBERT head.

Train the ModernBERT head

One encoder, one logistic, same hyperparameters as the packaged heads. The two sources of training rows are independent — use either, or concatenate both.

from sklearn.linear_model import LogisticRegression
from orchard.backends.modernbert import ModernBERTFeatureBackend
from orchard.backends.taxonomy_heads import HEAD_HYPERPARAMS, save_head

encoder = ModernBERTFeatureBackend()

def fit_head(texts, y):
    features = encoder.encode(texts)
    clf = LogisticRegression(
        C=HEAD_HYPERPARAMS["C"],                    # 0.1
        class_weight=HEAD_HYPERPARAMS["class_weight"],  # "balanced"
        max_iter=HEAD_HYPERPARAMS["max_iter"],      # 1000
        random_state=HEAD_HYPERPARAMS["random_state"],  # 20260725
    )
    clf.fit(features, y)
    save_head("topic_head.npz", clf.coef_, clf.intercept_, clf.classes_.tolist())
    return topic.load_head("topic_head.npz", encoder=encoder)

After load_head, taxonomy_transform is "modernbert_logistic". Save the npz; reload later without re-training.

A. Unsupervised — label descriptions only

No labelled corpus. Each label contributes its name. definition string, plus each cue as another row of the same class. ModernBERT sees the wording of the taxonomy itself.

texts, y = [], []
for label_id in topic.label_order:
    lab = topic.labels[label_id]
    texts.append(f"{lab.name}. {lab.definition}")
    y.append(label_id)
    for cue in lab.cues:
        texts.append(cue)
        y.append(label_id)

fit_head(texts, y)
# at least one row per class; cues help but are optional

Input: the definition you wrote above.
Procedure: ModernBERT-encode those short texts → logistic.
Result: topic_head.npz attached to topic.

B. Supervised — labelled documents / chunks

You already know the class of some texts. Encode those texts, not the label definitions.

from orchard import Document

chunks = [
    Document(text="Send an email digest of the inbox.", item_id="a"),
    Document(text="Reply-all to the thread.", item_id="b"),
    Document(text="Create a meeting on Tuesday.", item_id="c"),
    Document(text="Set a reminder for the offsite.", item_id="d"),
]
labels_by_item_id = {
    "a": "mail",
    "b": "mail",
    "c": "calendar",
    "d": "calendar",
}

texts, y = [], []
for doc in chunks:
    texts.append(f"{doc.title} {doc.text}".strip())
    y.append(labels_by_item_id[doc.item_id])

fit_head(texts, y)

Input: documents plus item_id → label_id (every value must be in label_order; at least two classes).
Result: the same topic_head.npz / attached head.

C. Both together (usual when you have any labels)

Stack description rows and document rows, then fit once.

texts, y = [], []

for label_id in topic.label_order:
    lab = topic.labels[label_id]
    texts.append(f"{lab.name}. {lab.definition}")
    y.append(label_id)
    for cue in lab.cues:
        texts.append(cue)
        y.append(label_id)

for doc in chunks:
    texts.append(f"{doc.title} {doc.text}".strip())
    y.append(labels_by_item_id[doc.item_id])

fit_head(texts, y)

Build a tree with it

from orchard import OrchardBuilder

orchard = OrchardBuilder(taxonomies=[topic]).build(chunks)
tree = orchard.tree("topic")
# custom names are taxonomy-JS only unless you set fusion weights —
# see Building Trees → Set fusion weights

Reload later without fitting again:

from orchard.backends.modernbert import ModernBERTFeatureBackend

topic = TaxonomyModel.load("topic.json")
topic.load_head("topic_head.npz", encoder=ModernBERTFeatureBackend())

Using the packaged Domain / Function heads

Skip training only if the AppWorld-style Domain / Function label sets match your documents. This is optional.

from orchard import DomainTaxonomy, FunctionTaxonomy, OrchardBuilder

domain = DomainTaxonomy.load_default()
function = FunctionTaxonomy.load_default()
orchard = OrchardBuilder(taxonomies=[domain, function]).build(documents)
# same as OrchardBuilder().build(documents) when orchard[ml] is installed

Offline lexical (rare)

No ModernBERT. Cue-word overlap, or the old TF-IDF taxonomy.fit(docs, labels). Almost never the right path when you can run ModernBERT. Explicit opt-in: OrchardBuilder(allow_offline_fallback=True) for packaged cue JSON, or pass a definition with no head (cue transform).

How the scores become a tree

Default similarity on taxonomy rows is Jensen–Shannon (taxonomy_similarity="jensen_shannon"). Alternative: "cosine". Layer name: {taxonomy_name}_raw_js (or {name}_cosine). To mix that layer with MiniLM and TF-IDF, set weights explicitly — Building Trees.
