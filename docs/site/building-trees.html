Building Trees

Building produces linkage — the hierarchy. Names do not change that structure. Label the tree before you judge whether a cut is good; fingerprints still work unlabeled.

Defaults (online)

OrchardBuilder().build(documents) needs orchard[ml] (MiniLM + ModernBERT). It builds domain and function trees. Fusion is variance_calibrated. MiniLM transform is "centered". Layer matrices are not saved unless you set layer_matrix_persist (recommended: "always" if you will cut with Calinski–Harabasz later). No label sets are created.

Procedure

  1. Load documents.
  2. Choose taxonomies (or none) and the text embedding (MiniLM vs TF-IDF).
  3. builder.build(documents) → an Orchard of trees (no node names yet).
  4. Label the tree you want to read.
  5. Compare fingerprints and cuts (Calinski–Harabasz).
from orchard import OrchardBuilder

builder = OrchardBuilder(layer_matrix_persist="always")
orchard = builder.build(documents)
print(orchard.tree_ids)          # ('domain', 'function')
print(builder.get_params())      # backends, weights, taxonomy_transform
domain = orchard.tree("domain")  # structure only; no labels yet

Routes

Online fused Domain + Function (usual)

Input: documents; MiniLM extra; ModernBERT extra.
Result: trees domain and function. Each fuses MiniLM + document TF-IDF + both taxonomy JS layers.

orchard = OrchardBuilder().build(documents)
assert orchard.tree_ids == ("domain", "function")

No-app weights (default): domain is mostly domain_raw_js (0.48) plus MiniLM 0.23, TF-IDF 0.14, function_raw_js 0.15. Function tree is the mirror (0.48 / 0.25 / 0.15 / 0.12). Variance-calibrated fusion needs n≥3.

No-taxonomy tree from semantic embeddings (MiniLM)

TF-IDF is not this path. This is MiniLM meaning similarity, optionally still mixed with a smaller TF-IDF lexical layer.

Input: documents; taxonomies=[]; MiniLM available or injected.
Result: one tree named semantic. Default weights: MiniLM 0.66 / TF-IDF 0.34.

from orchard import OrchardBuilder
from orchard.backends.minilm import MiniLMEmbeddingBackend

orchard = OrchardBuilder(taxonomies=[]).build(documents)
# or be explicit:
orchard = OrchardBuilder(
    taxonomies=[],
    embedding_backend=MiniLMEmbeddingBackend(),
    layer_matrix_persist="always",
).build(documents)
tree = orchard.tree("semantic")

To also keep this tree next to Domain/Function: include_semantic_with_taxonomies=True (default is False).

No-taxonomy tree from lexical TF-IDF

Overlapping words only. Pass the TF-IDF backend on purpose. Do not call this semantic.

from orchard import OrchardBuilder
from orchard.backends.tfidf import TfidfEmbeddingBackend

orchard = OrchardBuilder(
    taxonomies=[],
    embedding_backend=TfidfEmbeddingBackend(),
).build(documents)
tree = orchard.tree("semantic")   # tree id only; embedding is lexical
# weights: tfidf_cosine = 1.0

Offline fallback (explicit)

No MiniLM, no ModernBERT. Cue JS for each packaged taxonomy, TF-IDF-only for a no-taxonomy tree. Provenance records offline_fallback. This is not silent.

orchard = OrchardBuilder(allow_offline_fallback=True).build(documents)
# trees: domain + function, each own-taxonomy JS = 1.0
# taxonomy_transform == "cue"

Your trained taxonomy

from orchard import OrchardBuilder

# topic already has a ModernBERT head — see Taxonomies
orchard = OrchardBuilder(taxonomies=[topic]).build(documents)
# without profiles=, this tree is topic_raw_js only (weight 1.0)
# to mix MiniLM + TF-IDF + taxonomy JS, set weights (next section)

Train/load the head on Taxonomies.

Set fusion weights (explicit)

Each named tree is a weighted mix of independent [n, n] layers. There is no tree named fused. You pass a profiles dict keyed by tree id (the taxonomy name, or "semantic").

Rules: every key is a layer name that will exist at build time. Values are non-negative and must sum to exactly 1.0 (not repaired). Default fusion mode is variance_calibrated.

Layer names you can put in weights

Layer keyWhat it is
description_minilm_centered_cosineMiniLM semantic (default transform). Changes if you set description_transform.
tfidf_cosineLexical TF-IDF on document text.
{name}_raw_jsJensen–Shannon on that taxonomy’s ModernBERT probabilities. For name="topic" this is topic_raw_js.
{name}_cosineOnly if taxonomy_similarity="cosine".
app_exact_matchOnly with complete family_metadata_key metadata.

Custom taxonomy, fused (copy this)

from orchard import OrchardBuilder, SimilarityProfile

# weights must sum to 1.0
topic_weights = {
    "description_minilm_centered_cosine": 0.50,  # semantic MiniLM
    "tfidf_cosine": 0.20,                        # lexical TF-IDF
    "topic_raw_js": 0.30,                        # your taxonomy JS
}

builder = OrchardBuilder(
    taxonomies=[topic],
    profiles={
        "topic": SimilarityProfile(
            name="topic",
            weights=topic_weights,
            fusion_mode="variance_calibrated",  # default; or "raw_convex"
        ),
    },
    layer_matrix_persist="always",
)
orchard = builder.build(documents)
print(builder.get_params()["profiles"]["topic"]["weights"])
# {'description_minilm_centered_cosine': 0.50, 'tfidf_cosine': 0.20, 'topic_raw_js': 0.30}

Same thing as a plain dict (the dict key is the tree id; fusion_mode comes from the builder):

builder = OrchardBuilder(
    taxonomies=[topic],
    profiles={"topic": topic_weights},
    fusion_mode="variance_calibrated",
)

Override packaged Domain / Function

from orchard import OrchardBuilder, SimilarityProfile

orchard = OrchardBuilder(
    profiles={
        "domain": SimilarityProfile(
            name="domain",
            weights={
                "domain_raw_js": 0.48,
                "description_minilm_centered_cosine": 0.23,
                "tfidf_cosine": 0.14,
                "function_raw_js": 0.15,
            },
        ),
        "function": SimilarityProfile(
            name="function",
            weights={
                "function_raw_js": 0.48,
                "description_minilm_centered_cosine": 0.25,
                "tfidf_cosine": 0.15,
                "domain_raw_js": 0.12,
            },
        ),
    },
).build(documents)

Those numbers are the packaged no-app defaults. Change them; keep the sum at 1.0. Inspect whatever was used with builder.get_params()["profiles"].

No-taxonomy tree weights

OrchardBuilder(
    taxonomies=[],
    semantic_weights={
        "description_minilm_centered_cosine": 0.66,
        "tfidf_cosine": 0.34,
    },
)
# equivalent:
OrchardBuilder(
    taxonomies=[],
    profiles={"semantic": {
        "description_minilm_centered_cosine": 0.66,
        "tfidf_cosine": 0.34,
    }},
)

taxonomy_weights={"topic": topic_weights} is another way to pass the same mapping for a taxonomy tree if you are not using profiles.

Compare trees

Two trees can share the same documents and still differ in linkage. linkage_fingerprint does not need names. To decide whether a cut is good, label first — see Labels — then walk the cut.

Same linkage or not

a = orchard_a.tree("domain")
b = orchard_b.tree("domain")
same_structure = a.linkage_fingerprint() == b.linkage_fingerprint()
print(same_structure, a.leaf_count, b.leaf_count)

Cluster quality at a cut (Calinski–Harabasz)

This is the embedded tree-goodness score used by top_criterion="optimal". Prefer a saved feature matrix (MiniLM layer, TF-IDF layer, or a taxonomy JS matrix). Do not silently switch to silhouette.

from orchard import build_dynamic_cut
from orchard.cuts import get_optimal_cut_labels

# Preferred: layer saved at build time (layer_matrix_persist="always")
X = orchard.layer_matrices["description_minilm_centered_cosine"]
cut = build_dynamic_cut(
    tree,
    top_criterion="optimal",
    cut_optimizer="calinski_harabasz_score",
    feature_matrix=X,
    min_width=2,
    max_width=8,
)
print(cut["top_partition_count"], cut["cut_optimizer"])

# Direct k-search on the same matrix (no nested cut)
labels, k = get_optimal_cut_labels(
    tree.linkage,
    X,
    metric="calinski_harabasz_score",
)
print("best k", k)

If no layer matrix was saved, still run Calinski–Harabasz, but on cophenetic distances from the linkage. Say so out loud — that input is weaker, and it is not silhouette:

from scipy.cluster.hierarchy import cophenet
from scipy.spatial.distance import squareform

cophenetic = squareform(cophenet(tree.linkage))
cut = build_dynamic_cut(
    tree,
    top_criterion="optimal",
    cut_optimizer="calinski_harabasz_score",
    feature_matrix=cophenetic,   # explicit: C-H on cophenetic rows
)
print("feature source: cophenetic distances (no saved layer matrix)")
Do not omit feature_matrix.

Calling build_dynamic_cut(..., top_criterion="optimal") with no matrix currently selects silhouette on cophenetic distances. That is the wrong default for tree quality. Always pass cut_optimizer="calinski_harabasz_score" and a matrix (saved layer, or cophenetic if that is all you have).

Compare two structures at the same cut

from orchard import build_dynamic_cut, cut_partition_item_ids

def top_groups(tree, orchard):
    X = orchard.layer_matrices.get("description_minilm_centered_cosine")
    if X is None:
        X = squareform(cophenet(tree.linkage))
        print("warning: scoring", tree.tree_id, "with cophenetic distances")
    cut = build_dynamic_cut(
        tree,
        top_criterion="optimal",
        cut_optimizer="calinski_harabasz_score",
        feature_matrix=X,
    )
    return cut["top_partition_count"], cut_partition_item_ids(cut, tree)

k_a, groups_a = top_groups(tree_a, orchard_a)
k_b, groups_b = top_groups(tree_b, orchard_b)
print(k_a, k_b)
print(groups_a == groups_b)

Walk nodes by level (with or without leaves) while you compare — helpers are on Cuts & Views.

App-family layer

Default: off (family_metadata_key=None). Turn on only when every document has a non-empty value for that metadata key. Partial metadata raises; Orchard does not drop the layer and renormalize.

builder = OrchardBuilder(family_metadata_key="app_name")
orchard = builder.build(documents)
assert builder.get_params()["app_exact_match_active"] is True

When on, Domain/Function use the with-app weight dicts (app_exact_match=0.03). The no-taxonomy tree stays MiniLM 0.66 / TF-IDF 0.34. Offline and explicit TF-IDF-only paths stay single-layer.
