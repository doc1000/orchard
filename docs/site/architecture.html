Architecture

Orchard turns a fixed list of documents into persistent hierarchical trees. Building the tree and naming the nodes are two different jobs.

Defaults (online)

With orchard[ml] installed, OrchardBuilder().build(documents) builds named domain and function trees. Text similarity is MiniLM (semantic) fused with TF-IDF (lexical). Taxonomy scores come from packaged ModernBERT+logistic heads. Fusion mode is variance_calibrated. Labeling is off until you ask for it.

Two jobs

1. Build the tree

Documents → embeddings / taxonomy scores → similarity layers → fused matrix → SciPy linkage. The result is structure: who is near whom. Linkage does not depend on node names.

2. Label the nodes

Names are a presentation overlay. They never change linkage, memberships, or node IDs. Label before you judge a cut — without names there is little basis for saying a cut is good. An LLM is for this step, not for building the tree.

Words that get confused

TermMeaning in Orchard
Semantic embedding MiniLM vectors. Similar meaning. Default online text layer.
Lexical embedding TF-IDF vectors. Similar words. Layer name tfidf_cosine. Not semantic.
Taxonomy A label set plus a scorer. Each document gets a distribution over those labels. Online default is ModernBERT+logistic. Offline is cue words or a fitted TF-IDF logistic head.
Tree named "semantic" The no-taxonomy tree. Its embedding may be MiniLM, TF-IDF, or both. The name does not mean “semantic embedding.”

How a tree is built

Each split below is a real choice. Online defaults are marked.

1. Documents

A list of texts (or Document records). One document = one leaf. Corpus is fixed; you cannot add or remove items later.

↓
2. Text embedding — pick one path

Semantic (online default)

MiniLM (MiniLMEmbeddingBackend). Layer: description_minilm_centered_cosine.

Lexical (offline / explicit)

TF-IDF (TfidfEmbeddingBackend). Layer: tfidf_cosine. Overlapping tokens, not meaning.

Default fused trees use both layers (MiniLM 0.66 / TF-IDF 0.34 on the no-taxonomy tree; taxonomy trees mix MiniLM, TF-IDF, and taxonomy JS). A TF-IDF-only tree is an explicit opt-in.

↓
3. Optional taxonomy scores — pick one path

Online: ModernBERT classifier

Train your own head from label descriptions and/or labelled chunks, or load the packaged Domain / Function heads. taxonomy_transform: "modernbert_logistic". Needs orchard[taxonomy-ml]. See Taxonomies.

Offline: lexical taxonomy

Cue-word overlap, or fit() a TF-IDF + logistic head on your labels. No ModernBERT.

Or skip taxonomies: taxonomies=[] builds only the no-taxonomy tree named semantic.

↓
4. Independent similarity layers

Each signal becomes its own [n, n] matrix. Do not concatenate MiniLM, TF-IDF, and taxonomy into one feature vector. Optional: keep these matrices on disk (layer_matrix_persist) so later cuts can score Calinski–Harabasz without recomputing embeddings.

↓
5. Fuse (if more than one layer)

Weighted mix of the matrices. Default mode: variance_calibrated (needs n≥3). Alternative: raw_convex. Weights must already sum to 1.

↓
6. Linkage → Tree

Dissimilarity D = 1 − S, then average linkage. Canonical node IDs are assigned. No labels yet.

↓
7. Label (separate from build)

Intrinsic heuristic, imported names, or (later) an LLM. Switching label sets does not rebuild the tree. See Labels.

↓
8. Inspect, cut, compare

Walk levels, cut, and compare. Fingerprints work without names; reading whether a cut is good does not. Score cuts with Calinski–Harabasz. See Building Trees and Cuts & Views.

Core objects

  • Document — one corpus item (item_id, text, optional title/metadata).
  • TaxonomyModel — a label set plus transform(documents) → [n, k] scores. Input to a tree, not the tree itself.
  • Tree — SciPy linkage + canonical node IDs + optional named label sets.
  • Orchard — one shared corpus and one or more named trees.
  • OrchardBuilder — the only public construction verb is build (not fit_transform).

Rules that do not change

  • There is no tree named fused or mixed. Fusion happens inside each named tree.
  • ModernBERT is the taxonomy encoder. It is not the document embedding. MiniLM is the document embedding.
  • TF-IDF is lexical, not semantic.
  • Labels never mutate linkage.
  • The corpus cannot grow or shrink in place. Rebuild a new Orchard.
