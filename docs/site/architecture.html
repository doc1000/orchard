Architecture

OrchardBuilder builds durable trees. Orchard holds them. Cuts and subtrees are cheap views.

Core objects

  • Document — shared corpus leaf (item_id, text, …)
  • Tree — SciPy linkage + canonical node IDs + named label sets
  • Orchard — multi-tree collection over one corpus
  • TaxonomyModel — input signal; one tree per taxonomy name

Rules

  • Public construction verb is build, not fit_transform
  • Per-tree fusion (MiniLM + TF-IDF + taxonomy JS; optional app_exact_match); no orchard tree named fused / mixed
  • Independent [n,n] layers — do not concatenate feature vectors
  • Labels never mutate linkage
  • Incremental corpus mutation is unsupported
